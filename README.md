# MultiCloudflared

**Multiple Cloudflare tunnels. One Windows service. Familiar Cloudflare commands.**

[Download the latest Windows release](https://github.com/danhol86/multicloudflared/releases/latest) · [Setup guide](docs/SETUP.md) · [Commands](docs/COMMANDS.md) · [Report a problem](https://github.com/danhol86/multicloudflared/issues)

Run independent tunnels, including tunnels from different Cloudflare accounts, on one Windows PC. Add another token whenever you need another tunnel. No Docker, Node.js, Python, .NET installation or compilation needed.

## Download and install

**Windows 10/11 x64 or Windows Server x64. Administrator access required.**

1. Download **[multicloudflared-windows-x64.zip](https://github.com/danhol86/multicloudflared/releases/latest/download/multicloudflared-windows-x64.zip)**.
2. Right-click the ZIP → **Extract All**.
3. Double-click **Install.cmd** and accept the administrator prompt.
4. Open **MultiCloudflared** from the Windows Start menu, choose **Add tunnel**, and paste your Cloudflare tunnel token.

The installer downloads and verifies the official Cloudflared engine, installs an automatic Windows service, and creates the Start menu shortcut. The service keeps running after you close the window and starts after reboot.

**Prefer Cloudflare's command style?** Download [cloudflared.exe](https://github.com/danhol86/multicloudflared/releases/latest/download/cloudflared.exe), open Administrator PowerShell in its folder, and run:

```powershell
.\cloudflared.exe service install <TUNNEL_TOKEN>
```

Replace the placeholder with the token from Cloudflare. The EXE downloads the engine and installs/starts the service automatically. The standalone EXE route does not create a Start menu shortcut; use the ZIP installer for that.

**Add another tunnel with the same command:**

```powershell
.\cloudflared.exe service install <ANOTHER_TUNNEL_TOKEN>
```

No uninstall is needed between tunnels. Repeating the same token does not create a duplicate or restart its worker. A rotated token updates the matching tunnel.

> Use this project's executable, with **.\** or its full path. The upstream Cloudflare executable on your PATH still uses Cloudflare's original single-service installer.

## Get your token from Cloudflare

1. Open the [Cloudflare dashboard](https://dash.cloudflare.com/).
2. Open **Networking → Tunnels** (some dashboard layouts use Zero Trust → Networks → Connectors).
3. Create/select a **Cloudflared** tunnel, then open the connector installation instructions or **Add a replica**.
4. Choose **Windows / 64-bit**. Copy the token from the end of the command that looks like:
   `cloudflared.exe service install eyJ...`
5. Run that command with the MultiCloudflared EXE, or paste only the token into **Add tunnel**.
6. Configure your published application/hostname and origin in Cloudflare, for example `app.example.com → http://localhost:3000`.

[Cloudflare's setup guide](https://developers.cloudflare.com/tunnel/get-started/) · [Finding and rotating tokens](https://developers.cloudflare.com/tunnel/reference/tunnel-tokens/)

## Everyday commands

Run from Administrator PowerShell, in the folder containing your downloaded EXE:

| Action | Command |
| --- | --- |
| Install/add a tunnel | `.\cloudflared.exe service install <TOKEN>` |
| Add with a friendly name and hidden token prompt | `.\cloudflared.exe add personal` |
| Show tunnels | `.\cloudflared.exe status` |
| Stop/start one tunnel | `.\cloudflared.exe stop <NAME>` / `start <NAME>` |
| Restart one tunnel | `.\cloudflared.exe restart <NAME>` |
| View logs | `.\cloudflared.exe logs <NAME>` |
| Remove one tunnel locally | `.\cloudflared.exe remove <NAME>` |
| Stop/start all tunnels | `.\cloudflared.exe service stop` / `service start` |
| Uninstall service, keep settings | `.\cloudflared.exe service uninstall` |

Names generated by **service install TOKEN** are the tunnel UUIDs shown by **status**. The **add NAME** command lets you choose your own name. Adding a tunnel saves it; the manager service must be running to connect it.

## Update

Double-click **Update.cmd** in the extracted ZIP or installation folder. It downloads the latest GitHub release, checks its SHA-256 digest, replaces the installed manager, and preserves tunnel settings. Managed engine versions follow the app release; explicitly configured custom engine paths are preserved. Workers reconnect during an update.

Alternatively, download the new EXE and run:

```powershell
.\cloudflared.exe service upgrade
```

Use the newly downloaded EXE, not the installed copy. No need to uninstall first.

## Uninstall

- **One tunnel:** `.\cloudflared.exe remove <NAME>`.
- **Service only:** `.\cloudflared.exe service uninstall` stops all managed workers and removes the service; files/settings remain.
- **Application:** double-click **Uninstall.cmd**. Removes the service, installed binaries and Start menu shortcut; preserves encrypted settings so you can reinstall.
- **Everything, including stored tokens and logs:** from Administrator PowerShell, run `.\Uninstall.ps1 -Purge`.

None of these deletes your remote Cloudflare tunnels, DNS records, or another Cloudflared installation.

## How it works

One manager service supervises one official Cloudflared worker process per tunnel. All workers share one engine executable file. This is a manager around Cloudflare's engine, not a replacement tunnel protocol or a single worker serving multiple tunnel identities.

Tokens are DPAPI-encrypted on this Windows machine. Settings/logs live under `C:\ProgramData\CloudflaredNew`, restricted to Administrators and SYSTEM. Installed files live under `C:\Program Files\CloudflaredNew`. The service name remains **CloudflaredNew** for compatibility with the first version.

The token supplied to **service install TOKEN** is briefly visible in the installing command's arguments and may enter shell history. Use the hidden **add NAME** prompt if preferred. Tokens are never put into worker/service command lines.

## Supported scope

- Windows x64; remotely managed, token-based Cloudflare tunnels.
- Multiple accounts/tunnels; independent retries; hot configuration reload; rotating logs.
- Existing upstream **Cloudflared** service can remain installed.
- **Connected** reflects a Cloudflare connection registration, not a complete website availability test.
- macOS/Linux, ARM64, local YAML tunnel configurations and all upstream CLI commands are not implemented.
- Unsigned community build. Only download from this repository's releases; Windows may show an unknown-publisher prompt.

## Build and release

Developers need the .NET 10 SDK:

```powershell
.\build.ps1
dotnet build .\tests\FakeEngine -c Release
powershell -ExecutionPolicy Bypass -File .\tests\Integration.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\Package.ps1
```

GitHub Actions builds and tests pushes/PRs. Pushing a version tag such as **v1.1.0** builds a release ZIP, standalone EXE and SHA-256 checksums, then publishes them to GitHub Releases after tests pass. No private tunnel credentials are required for the automated tests.
